# Qwen Image Edit + OpenPose on Runpod

This is an experimental Runpod ComfyUI worker for the Civitai Qwen Image Edit + InstantX Union ControlNet graph. It uses Nunchaku's FP4 8-step edit model for Blackwell GPUs. The Union ControlNet's official base is Qwen Image, so its behavior with Qwen Image Edit requires an actual GPU test.

The Dockerfile extends `runpod/worker-comfyui:5.10.0-base-cuda12.8.1`. It must be built for `linux/amd64` and deployed as a Runpod queue Serverless worker. The image contains about 25 GB of public model weights. No API keys should be baked into it.

Build requirements: a Linux Docker builder with a registry, or Runpod's GitHub integration connected to the repository. The Dockerfile installs Nunchaku's official Linux wheel for Python 3.12, PyTorch 2.11, and CUDA 12.8, then checks that it imports. Do not deploy a failed build.

For the managed GitHub builder, connect the PCAG repository in Runpod and set the Dockerfile path to `tools/sprites/runpod-qwen/Dockerfile`. The builder uses the repository root as its build context. Keep `.env` out of Git; the Dockerfile does not copy the repository into the image. Build completion and worker startup must both be checked before sending the first frame.

The deployed test endpoint is [`PCAG Qwen Edit OpenPose`](https://console.runpod.io/serverless/user/endpoint/4o82a1di5juzij) (`4o82a1di5juzij`). It is pinned to `NVIDIA RTX PRO 4500 Blackwell`, one GPU, 50 GB container disk, CUDA 12.8 minimum, zero minimum and one maximum worker, and a 5-second idle timeout. The published image is from commit `c41cbda` and includes the pinned upstream fix for Qwen's positional argument mismatch in the Nunchaku adapter. Runpod's serverless catalog listed this GPU at $1.15 per active worker hour when checked on October 24, 2026.

The source Civitai download is a GUI graph, not ComfyUI's API graph. `submit.py` assembles an API graph with the nonessential Easy Use and rgthree nodes removed, crops the right-facing dummy from the turnaround sheet, removes the sheet background, and sends it with one OpenPose frame. Run `python tools/sprites/runpod-qwen/submit.py --dry-run` to inspect the request size, then `python tools/sprites/runpod-qwen/submit.py --endpoint-id 4o82a1di5juzij --frame 0` to generate one frame. The result is saved under `generated/qwen-runpod/`. Use `--denoise` and `--control-strength` to experiment. If a client wait expires, add `--job-id JOB_ID` to retrieve that same job without submitting another one.

The endpoint builds and runs the full graph, but the first image tests are not suitable for an animation atlas. With denoise 0.72 and ControlNet strength 1.2, [frame 0](../../../generated/qwen-runpod/revised/frame_00_0.png) has distorted anatomy and invented facial features. With denoise 0.5 and ControlNet strength 1.4, [frame 2](../../../generated/qwen-runpod/low-denoise/frame_02_0.png) preserves the dummy better but remains close to the standing reference instead of following the bent-leg OpenPose guide. These outputs are 800 × 1328 pixels; they have not been turned into 90 × 160 sprite frames. Do not batch the other six frames until the pose guidance works reliably. The linked Civitai item is a workflow archive, not a separate ControlNet model: its required model list names the same InstantX Qwen Image Union ControlNet used here. That ControlNet targets Qwen Image, while this graph uses Qwen Image Edit, so compatibility remains a likely limitation rather than a proven cause of the weak pose response.
